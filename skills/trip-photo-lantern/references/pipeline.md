# 每一步怎么算

## 1 scan：读照片

- 递归读取 JPG / PNG / HEIC / WebP / TIFF。HEIC 优先用 `pillow-heif`；没装且在 macOS 上时，用系统自带的 `sips` 转成 JPEG。
- 按 EXIF 方向转正，按内嵌 ICC 转到 sRGB，长边缩到 2400 像素，存成 `work/src/0001.jpg`…。保存时不写 EXIF 和 ICC，工作副本里没有任何元数据。
- 从原文件读出拍摄时间和 GPS，只写进本机的 `work/manifest.json`，用来挑片时避开同一时间、同一地点的连拍。
- 预筛分：画面顶部四分之一越亮、越平滑（像天空），整体越不暗，分数越高。

## 2 mask：本机语义分割

- 模型：`openmmlab/upernet-convnext-tiny`（UperNet + ConvNeXt-T，ADE20K 150 类，MIT 许可）。
- 预处理按官方 preprocessor_config：缩放到 512×512（双线性）、除以 255、ImageNet 均值方差归一化。
- 每张输出天空概率图 `work/masks/<id>_sky.png`，以及天空、人物、建筑、植被的面积占比 `work/masks/<id>.json`。
- Apple 芯片上先试 MPS；UperNet 的金字塔池化在部分 PyTorch 版本的 MPS 上会报错，报错就自动用 CPU。

## 3 pick：挑 8 张

每张照片在 256 像素宽的缩略图上算：

| 指标 | 含义 | 喜欢的范围 |
|---|---|---|
| top | 顶边是天空的列占比 | 越高越好 |
| frac | 天空面积占比 | 0.15–0.6 |
| struct | 天际线高度的标准差（起伏） | 0.04–0.2 |
| tv | 相邻列天际线高度差的均值（锯齿） | ≤ 0.035 |
| sky_lum | 天空亮度中位数 | ≥ 0.45（夜景天空太暗，剪出来全是碎洞） |
| holes | 地面里比天空还亮的面积占比 | ≤ 0.05 |

总分 = top^1.5 × 各项钟形函数之积。人物面积超过 `--max-person`（默认 0.2%）的照片不参加。

去重：按分数从高到低贪心选，和已选的每一张都要「够远」：拍摄时间相隔 ≥ 30 分钟、GPS 相距 ≥ 0.5 km、画面差异哈希（dHash）≥ 14 位，且不能「画面像、天际线形状也像」。凑不满 8 张就逐级放宽。选好后按拍摄时间排成一圈。

## 4 strip：剪纸与灯筒展开图

- 剪影：天空概率图以原图亮度为引导做导向滤波（r = 6，ε = 0.002），阈值 0.5 得到天空；地面里比天空中位亮度 × `--hole-gain` 还亮的成片区域（灯火、窗、瀑布）刻成镂空，先腐蚀再膨胀去掉水面反光的碎点；最后轻微模糊再阈值，得到剪纸边。
- 每张取正方形，让天际线落在格子 46% 高处。
- 展开图 8192×2048：第 0–23 行顶边纸条；384–1407 行是 8 格天际线（格间 14 像素纸条）；1408 行以下是微透光的实纸（灰度 200），1560–1640 行刻一圈回纹，1680–1688 行一道细缝。
- 同时输出 `strip_photo.jpg`（每格对应的原照片，用于「影子变回照片」）和 `panels.json`（每格的地名、日期、u 范围）。

## 5 html：单文件网页

- 运行时 `assets/runtime/lantern.bundle.js` 由 `src/app.js` + `src/lantern-core.js` + three.js r186 打包而成（`scripts/build_runtime.sh` 可复现）。
- 剪纸图以 PNG、照片图缩到 4096×1024 以 JPEG 内嵌成 data URL；地名和日期以 JSON 内嵌。网页不发任何网络请求。

## 渲染原理（lantern-core.js）

不用阴影贴图，而是解析计算每一条光线：从烛焰出发，依次穿过内筒剪纸、八角灯罩的宣纸与木骨，再落到墙上。

- 内筒遮挡：求光线与半径 0.30 的圆柱交点，换算成剪纸贴图的 (u, v) 采样；按「烛焰大小 ×（墙距 − 筒距）/ 筒距」估算半影宽度，换成贴图的 mip 层级，所以离灯越远的影子越柔。
- 灯罩：宣纸透光带暖色，木骨和上下边框按位置遮挡。
- 「影子变回照片」：在点按处画一个逐渐变大的圆，圆内、且属于同一格剪纸的墙面，改为采样那一格的原照片，再乘以同样的光照。
